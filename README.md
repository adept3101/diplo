# Разработка веб-приложения для прогнозирования котировок валют с нейросетевой коррекцией

Веб-приложение для работы с валютными котировками на основе данных Центрального банка Российской Федерации (Банка России). Проект разработан в рамках дипломной работы и объединяет получение финансовых данных, серверную обработку, машинное обучение и пользовательский веб-интерфейс.

## О проекте

Цель проекта — разработать веб-приложение, которое использует исторические данные о курсах валют и методы машинного обучения для повышения качества анализа и прогнозирования валютных котировок.

Приложение получает данные из открытого API Банка России, обрабатывает их на стороне backend и использует нейросетевую модель для коррекции прогноза или оценки динамики валютного курса.

### Основные задачи

- Получение данных о валютных курсах из API Банка России.
- Обработка и хранение данных в базе PostgreSQL.
- Разработка REST API для взаимодействия frontend и backend.
- Реализация регистрации, авторизации и управления профилем пользователя.
- Подготовка исторических данных для обучения нейросетевой модели.
- Интеграция модели машинного обучения в серверную часть приложения.
- Создание веб-интерфейса для взаимодействия с пользователем.

## Требования

Для локального запуска потребуются:

- Python 3.13 — если backend запускается без Docker.
- React и npm — для frontend.
- PostgreSQL — если база данных не запускается в отдельном контейнере.
- Docker — для контейнеризированного запуска backend.

Версии Node.js и PostgreSQL следует выбирать с учётом зависимостей проекта.

## Быстрый запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/adept3101/diplo.git
cd diplo
```

### 2. Настройка переменных окружения

Создайте файл `.env` в соответствии с настройками backend.

В нём могут потребоваться параметры подключения к PostgreSQL, секретный ключ JWT и адрес внешнего API.

Примерный набор переменных:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
SECRET_KEY=replace_with_a_secure_secret
```

Названия переменных должны соответствовать тому, что фактически читает приложение. Не добавляйте реальные секреты и пароли в Git.

### 3. Запуск backend через Docker

Сборку образа необходимо выполнять из каталога, в котором находится Dockerfile:

```bash
docker build -t diplo-backend ./back
```

Запуск контейнера:

```bash
docker run --env-file back/.env -p 8000:8000 diplo-backend
```

Этот пример предполагает, что сервер слушает порт `8000`, а приложение корректно настроено на запуск внутри контейнера.

Если PostgreSQL работает на хостовой машине или в другом контейнере, дополнительно настройте доступ к базе данных. Контейнер backend не сможет автоматически обратиться к базе по адресу `localhost`, если база находится вне этого контейнера.

### 4. Запуск frontend

Откройте отдельный терминал:

```bash
cd front
npm install
```

Запустите приложение командой, предусмотренной конфигурацией проекта:

```bash
npm run dev
```

Перед запуском убедитесь, что frontend настроен на обращение к правильному адресу backend.

### 5. Проверка работы

После запуска backend проверьте доступность API и документации FastAPI:

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs

Адреса документации доступны, если соответствующие маршруты не отключены в конфигурации FastAPI.

## Безопасность

- Не храните секретные ключи, пароли и другие чувствительные данные в репозитории.
- Используйте переменные окружения для конфигурации приложения.
- Применяйте безопасную генерацию и хранение секретного ключа JWT.
- Проверяйте права доступа к защищённым API-маршрутам.
- Не используйте тестовые учётные данные в рабочем окружении.

## Ограничения

Результаты работы нейросетевой модели зависят от качества исторических данных, выбранного периода обучения и характеристик модели.

Официальные курсы Банка России являются справочными значениями и не обязательно отражают цены сделок или котировки, доступные для немедленной покупки и продажи на бирже. Поэтому при интерпретации результатов необходимо учитывать особенности источника данных.
